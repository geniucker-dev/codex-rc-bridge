# Codex RC Bridge

[English](README.md) | 简体中文

让 Codex 远程控制跨 ChatGPT 账号使用。

比如手机上登录的是个人账号，公司电脑上的 Codex 用的是另一个账号。ChatGPT 自带的远程控制只能连同一个账号下的电脑。Codex RC Bridge 在两个账号之间转接，让你在手机、平板或电脑上的 ChatGPT 里，像打开自己的电脑一样打开那台电脑。

## 非官方项目

Codex RC Bridge 是独立的开源项目，不是 OpenAI 开发的，也没有得到 OpenAI 的认可或支持。它通过官方应用使用的远程控制接口与 ChatGPT 通信，而这些接口 OpenAI 并没有向其他软件公开。OpenAI 随时可能修改或封锁这些接口，桥接也可能因此毫无预兆地失效。使用风险由你自己承担，同时仍要遵守 OpenAI 的条款。

只用它连接属于你自己的 ChatGPT 账号。不要用它让别人使用你的账号或订阅，OpenAI 的账号共享政策不允许这样做。

桥接会保存你添加的每个账号的登录凭据，用一把和数据库分开存放的密钥加密。它用这些凭据为这些账号注册远程控制设备，并转发它们的会话。运行桥接的人掌握这把密钥，所以在服务器上，部署管理员理论上可以使用上面所有人的登录凭据。请自己运行桥接，或者只使用你信任的人运行的服务器。

在桥接里删除控制端或被控端时，桥接会去 ChatGPT 撤销它的访问权限；撤销失败时，它会保持停止，直到清理成功。在服务器上删除用户则不会撤销任何东西，那个用户的 ChatGPT 里可能还会留着已经无法使用的远程设备。

## 它怎么工作

桥接里只有两样东西，一条连接把它们接起来：

- 控制端：你用来发起控制的那台设备，可以是手机、平板，也可以是电脑上的 ChatGPT。每个控制端只配对一台设备，用这台设备上 ChatGPT 登录的账号。
- 被控端：你要控制的那台电脑，上面运行着开启了远程控制的 Codex。每个被控端只对应一台电脑，用这台电脑上 Codex 登录的账号。

在管理页面里把一个控制端连到一个被控端，这台电脑就会出现在控制端设备的 ChatGPT 里，成为一台远程设备。两边的账号可以不同。

可以同时建多组。同一台手机要控制两台电脑，就建两个控制端，各连一个被控端。两个被控端也可以指向同一台电脑。

桥接要一直运行，被控电脑上的 Codex 也要开着远程控制。用来控制的那台设备只需要 ChatGPT，不用运行桥接。

## 选择运行方式

|          | 桌面版                             | 自建服务器                           |
| -------- | ---------------------------------- | ------------------------------------ |
| 适合     | 桥接和被控电脑在同一台 Mac 上      | 放在一直开着的主机上，或者给多人共用 |
| 管理方式 | macOS 应用                         | 浏览器，手机浏览器也可以             |
| 用户     | 一个人用，可以添加多个账号和连接   | 每个人有独立的空间                   |
| 后台运行 | 关闭窗口后继续运行，退出应用才停止 | 关闭浏览器后继续运行                 |

界面支持英文和简体中文，默认跟随系统语言，其他语言显示英文。网页可以在顶部切换，桌面版在“设置”里切换。

## 开始使用

### 桌面版（macOS）

从 [Releases](https://github.com/geniucker-dev/codex-rc-bridge/releases) 下载 `.dmg`：Apple Silicon 选 `macos-arm64`，Intel 选 `macos-x64`。打开后把应用拖进“应用程序”，无需安装 Rust 或 Bun。

应用使用 ad-hoc 签名，未经 Apple 公证。首次打开被拦截时，在“系统设置 → 隐私与安全”里选择“仍要打开”，详见[安装说明](docs/guide/desktop.zh.md#安装)。尚无正式版本时，可以从 GitHub Actions 下载测试构建，或按[开发指南](docs/guide/development.zh.md)自行构建。

第一次打开时，先在“设置”里选直连或填写 HTTP 代理，再按下面的步骤添加连接。后台运行、授权回调、数据位置和备份见[桌面版指南](docs/guide/desktop.zh.md)。

### 服务器（Docker Compose）

Docker Hub 上有现成的 x64 和 arm64 镜像。需要装好 Docker 和 Compose 的主机，以及一个反向代理（如 Caddy 或 nginx），用 HTTPS 提供你的域名，并转发到桥接的 `127.0.0.1:8787`：

```sh
mkdir codex-rc-bridge && cd codex-rc-bridge
curl -fsSLO https://github.com/geniucker-dev/codex-rc-bridge/releases/latest/download/compose.yaml
curl -fsSL -o .env https://github.com/geniucker-dev/codex-rc-bridge/releases/latest/download/compose.env.example
# 把 .env 里的 BRIDGE_PUBLIC_ORIGIN 改成你的 HTTPS 地址
docker compose pull
docker compose run --rm admin init
docker compose run --rm admin add-user TENANT_UUID admin
docker compose up -d server
```

`TENANT_UUID` 换成 `init` 输出的那个值。`add-user` 会先问上游代理（直接回车表示直连），再让你设一个至少 12 位的密码。然后打开你的 HTTPS 域名，用 `admin` 登录。这个登录只用于桥接的管理页面，和 ChatGPT 账号无关。

反向代理的配置、添加其他用户、上游代理、升级、备份和不用 Docker 的安装方式，见[服务器部署指南](docs/guide/server.zh.md)。

## 连上第一台电脑

桌面版和网页的操作一样。“远程控制”页左边一列是控制端，右边一列是被控端。

1. 新建被控端：选择被控电脑上 Codex 登录的账号，起个名字。接着会进入授权，授权保存后，输入电脑上 Codex 显示的配对码。
2. 新建控制端：选择用来控制的那台设备上 ChatGPT 登录的账号，起个名字。页面会显示一个配对码，在那台设备的 ChatGPT 里打开远程控制并输入。配对成功后，弹窗会显示设备名称。
3. 连接：在还没连接的控制端上点“连接被控端”，选择刚才的被控端，连接会立即启动。之后在控制端设备的 ChatGPT 里打开这台远程设备。

账号还没登录时，两个对话框里都可以直接添加账号。

授权时，打开或复制页面给出的链接，用这一步要求的账号登录。桌面版会自动接收登录结果。服务器版需要把浏览器最后跳转到的完整地址粘贴回管理页面，即使浏览器显示 `localhost` 打不开也没关系。

## 日常使用

“远程控制”页上，每条连接画成一根线，线上写着连接状态。哪一端出了问题，那一端的卡片就会标出来，写明原因和修复方法：需要重新登录账号、被控端需要重新授权、控制端需要重新注册，或者设置还没完成。照着卡片上的按钮操作即可，修好后连接会自动恢复。

- 停止：暂停连接，两边的配对都保留，再次启动不用重新配对。
- 切换被控端：把控制端改连另一台电脑，原来的电脑会先断开。手机上切换后，刷新一下设备页面或者重新进入。
- 重新配对设备：控制端换了设备，或者设备丢了，就在控制端页面重新配对。原来的设备会先被移除，再显示新的配对码。
- 重新配对电脑：电脑重装或换了一台，就在被控端页面重新配对。原来那台电脑的访问会先被撤销。
- 被控端显示离线：说明那台电脑现在连不上，等它重新上线后会自动重连。

“账号”页把需要重新登录的账号排在最前面，并列出用到它的控制端和被控端。点“检查全部登录”可以一次检查所有账号。

## 用电脑上的 ChatGPT 控制时

建议每台被控电脑单独用一个控制端，不要来回切换。电脑上的 ChatGPT 会按控制端记住你打开过的远程项目和文件夹路径。把同一个控制端切到另一台电脑后，旧项目的路径可能会被用在新电脑上。
