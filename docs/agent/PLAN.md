# Codex RC Bridge 正式项目计划

更新日期：2026-11-08。

此文档记录目标设计、约束和完成标准，以用户最后确认的要求为准。实施进度见[第 8 节](#8-实施顺序与完成标准)，使用入口见 [README](../../README.md)，协议证据与旧 PoC 资料见 [REFERENCE](REFERENCE.md)。

## 1. 目标与版本范围

核心目标是跨账号 Remote Control：控制端 A 使用账号 A，目标 B 使用其他账号，桥接器通过 IN/OUT 连接两侧。手机无需运行桥接应用。

```text
手机 / 官方控制端 A → 官方 relay A → IN → OUT → 官方 relay B → 被控设备 B
```

提供两种部署形态，复用同一 Rust 核心和主要管理界面：

|               | 桌面版                              | 服务器版                      |
| ------------- | ----------------------------------- | ----------------------------- |
| IN / OUT 数量 | 多个                                | 多个                          |
| 典型位置      | 常与被控电脑一起运行，也可独立运行  | 常驻服务器                    |
| 管理入口      | 桌面界面                            | 手机浏览器可用的网页          |
| 租户          | 默认一个本地空间                    | 多用户，各自独立空间          |
| 存储          | SQLite 与受保护的本地秘密存储       | SQLite 与独立提供的加密主密钥 |
| 运行方式      | 窗口/托盘明确区分，退出应用停止桥接 | 关闭网页不影响后台转发        |

### V1：跨账号远控与硬切换

- 多 IN、多 OUT；每条桥接链保存 IN、OUT 和目标 B 的配置关系。
- 每条链可独立启停、自动重连、续期和删除。
- 一个 IN 同时只绑定一个 OUT；一个 OUT 同时只被一个 IN 绑定。
- 独占属于保存的配置关系。离线、暂停、授权暂时不可用或重连都不释放绑定；明确解绑/删除才释放。
- 不同 OUT 允许连接同一个 B，分别使用自己的设备身份、密钥和上游注册。
- 多个手机使用不同账号时，为各账号建立 IN，再分别绑定独立 OUT。
- V1 支持同一个 IN 改绑另一个 OUT，采用先断开旧链路、再建立新链路的硬切换。任何已有链路的目标变化都必须经过同样的关闭与重新初始化边界，不能直接修改运行中的转发目标。
- 若同一个 A 希望访问多个 B，可以为各目标建立独立 IN/OUT 组合，也可以在管理界面切换同一个 IN 绑定的 OUT。
- 桌面和服务器都实现上述能力；服务器增加管理登录和租户隔离。

V1 交付完整的身份、授权、绑定、硬切换、删除、恢复和租户隔离能力。切换允许暂时离线，允许手机端需要退出设备页面后重新进入；旧消息隔离和新目标初始化必须在 V1 验证。

### V2：优化切换体验

- 缩短切换的离线时间，改善进度和失败反馈。
- 在官方客户端实际支持的范围内减少手动重新进入步骤，改善元数据和对话列表刷新。
- 优化必须保持 V1 的旧流隔离、独占和失败处理约束；不通过跨目标重放旧业务来制造连续连接的表象。

不为切换引入对象级运行实例 ID；使用已有设备身份、流标识、串行操作和必要的持久操作状态。

### V1 硬切换的边界

1. 校验新 OUT 的租户归属和配置独占，并在协调切换期间保留其使用权；并发改绑、删除和启停不能各自绕过此约束。校验失败不先拆掉旧链路。
2. 让 IN 停止接收新的转发请求、进入离线状态，关闭旧流与连接，终止并等待旧链路任务结束。发送取消信号本身不代表可以改绑。
3. 旧映射、未确认业务队列、分片及迟到响应不能进入新目标。保留识别旧流和拒绝历史重放所必需的记录；各端点 cursor 仍属于其各自上游历史，不能互换，也不能简单清零后把旧消息当作新请求。
4. 在事务与独占约束下提交新绑定、释放旧 OUT，再建立新链路；新目标真实可用后才让 IN 上线。后续连接失败显示新目标连接失败并保持离线，不静默回到旧目标。中途进程退出后按持久配置/操作状态恢复，状态未确定时先保持离线。
5. 官方手机端必须形成新目标的连接与初始化，不能沿用旧目标的流。验证设备元数据、对话列表以及旧请求/审批的归属；V1 可以要求用户重新进入设备，但不能只以 WebSocket 已重连作为切换成功依据。

硬切换保留 IN/OUT 设备 ID、密钥、登录、注册及已有配对，不触发删除流程。断开远控连接也不等于停止 B 上已经开始执行的任务；桥接不额外发送取消任务命令。

## 2. 对象与绑定

| 对象     | 职责                                                              |
| -------- | ----------------------------------------------------------------- |
| Tenant   | 隔离管理用户的账号授权、端点、秘密、绑定和运行状态                |
| 账号授权 | 某个真实 ChatGPT 账号及工作区的普通 OAuth 登录与续期              |
| IN       | 在 A 账号下呈现的虚拟被控设备身份                                 |
| OUT      | 用于控制 B 的设备身份、固定签名密钥、上游注册和配对               |
| 绑定关系 | 同租户内一个 IN 与一个 OUT 的独占连接关系，目标变化通过硬切换提交 |
| 运行会话 | 当前链路的 socket、映射、发送队列、接收与重放进度                 |

同一个账号可以拥有多个 IN 或 OUT；同账号的不同 OUT 用不同固定身份名区分。账号授权与端点身份分开建模；若同租户内复用普通登录凭据，refresh token 的轮换由同一授权管理器协调。

界面只呈现两种对象，并在创建时把内部对象固定组合：控制端是一个 IN 及它唯一的一台设备（手机、平板或桌面 ChatGPT）；被控端是一个 OUT 及它唯一的一台电脑（环境）。两侧都是“一台设备控制一台电脑”，同一台设备要控制多台电脑时，为每台电脑各建一个控制端。绑定关系在界面上表现为“控制端 → 被控端”，可以连接、切换和断开；IN 与 OUT 只在详情和修复处出现。

一个 OUT 最多对应一台电脑。新建被控端依次建立 OUT、完成授权并配对，配对后 OUT 可访问的环境恰好一个，保存为目标并记录名称，不再从环境列表中自由选择。电脑重装、环境失效或改用另一台电脑时“重新配对”：先撤销该 OUT 对当前全部环境的访问并确认已清空，再用新配对码配对，结果同样须恰好一个环境。撤销未完成时保留原目标与绑定，可以重试；旧环境已不存在时，以列表中不再有该 OUT 作为清理完成，这一点待真实账号验证。账号授权失效时重新授权 OUT，目标不变。已有多个环境的旧 OUT 保留当前目标，下次重新配对时清理其余环境。已绑定且运行中的被控端重新配对时，先停止并等待该链路退出，成功保存目标后恢复原启停状态，并提示控制端可能需要重新进入设备。撤权、配对或保存未完成时保留原目标、绑定及启用意图，保持离线；重试成功后恢复。重新配对前保存未完成状态，重启不会绕过该状态连接旧目标。

绑定约束必须在应用层和数据库事务中落实，不能只靠前端过滤列表。并发请求竞争同一 OUT 时只允许一个成功。运行任务有明确所属链路，停止其中一条不影响其他链路。

多个 OUT 控制同一个 B 是共享同一个实际工作环境，不提供 B 内部对话、项目和文件的租户隔离；桥接负责自己的凭据和消息归属。

## 3. 稳定设备身份与同名恢复

每个租户有独立、随机、长期保存的秘密种子。身份使用账号的稳定标识（包含所选工作区/用户的必要绑定），不使用邮箱或显示昵称代替。

固定身份名在端点创建时确定；可变的显示名不参与派生。名称编码、大小写/空白处理、字段编码、输出格式及 P-256 密钥生成方法在实现前固定，并用测试向量保证跨平台和跨版本一致。

首版具体编码及派生规则已记录在 [IDENTITY.md](IDENTITY.md)，固定向量由 Rust/AWS-LC 与 Bun WebCrypto/OpenSSL 分别验证。

```text
身份输入 = 无歧义编码(租户稳定身份、账号稳定身份、固定身份名)

in/id        + 身份输入 + 租户秘密种子 → IN 设备身份 ID
out/id       + 身份输入 + 租户秘密种子 → OUT 设备身份 ID
out/signing  + 身份输入 + 租户秘密种子 → OUT 签名密钥材料 → P-256 密钥
```

- 使用 HKDF 等已选定密码学原语做确定性派生，底层调用密码学库；不自写椭圆曲线实现。
- 用途标签分开公开 ID 与秘密密钥材料，也区分同名 IN 和 OUT。
- 用途标签及派生规则是常量，不加入应用版本或每次运行随机数；更新应用不能改变已有 ID/公钥。
- OUT 的签名密钥在该设备身份生命周期中固定，不提供原地轮换；需更换签名密钥时创建新的设备身份。
- 存储加密主密钥的更换不改变设备 ID、租户身份种子或 OUT 签名密钥。
- 本地可派生 ID 与官方服务分配的 `server_id`、`environment_id`、远控 `client_id` 分开保存，不能用本地值伪造服务端字段。
- OAuth 应用 client ID 代表应用，遵循已验证协议；它不是每个 OUT 的远控 client ID。

恢复范围已明确：同租户秘密种子、同账号、同固定身份名恢复相同的本地设备 ID 和 OUT 密钥。旧上游注册 ID、登录凭据、配对关系不要求恢复，重新登录/授权/配对符合预期。

租户秘密种子必须保住并备份；删除单个端点不销毁它。确定性恢复不能代替租户种子的持久化。

同名恢复就是同一设备重新授权，不引入对象级运行实例 ID。改绑、删除、续期及授权提交按相关设备协调和串行处理，删除完成后才允许重新创建/授权。删除完成意味着远端清理已确认，旧任务已经结束或不能再提交写入；发出取消信号本身不代表完成。被删除的 OAuth 事务失效，旧回调由现有一次性 state/事务校验拒绝。

## 4. 授权与删除

### 已验证的能力

用户在本次规划中明确确认：服务器发起、用户在自己设备浏览器完成并提交回调的授权，以及同密钥重新注册，早已验证可行。将它们作为已成立的设计输入。新语言实现仍做集成回归，但不重新设置可行性研究或批准门槛。

PoC 已验证的软件密钥、普通登录、OUT 二次授权和设备证明流程继续作为协议依据。软件存储的真实保护方式如实描述，不把协议中已有的保护类别字段当作实际硬件保证。

### 统一授权流程

- 桌面端可以自动接收本地 localhost 回调。
- 服务器创建授权事务，保留 PKCE verifier、state、redirect URI、所属租户和操作目标；用户打开该事务生成的链接，完成登录/授权后提交完整回调地址。
- 后端解析并校验回调，只向固定的官方 token endpoint 兑换令牌；不访问用户提交的 localhost URL。
- 回调事务一次性、限时、绑定当前用户和对象；校验返回账号与工作区符合预期。
- 普通 OAuth 与 OUT 远控二次授权分别处理；如加入设备码普通登录，也不据此跳过 OUT 的二次授权。
- 新同名端点恢复身份后不继承本地旧授权、注册和配对记录。是否完成远端撤权由删除流程的确认结果决定，不能由本地记录消失推断；之后按协议重新授权/注册/配对。

### IN 的控制端管理

一个 IN 只配对一台控制设备（手机、平板或桌面 ChatGPT），设备名称、平台和型号保存到本地快照。换设备使用“重新配对设备”：先撤销该 IN 环境下的全部设备，确认清空后再发新码，不提供设备列表或逐个撤权接口。删除 IN 仍按该环境撤销全部设备，不影响其他 IN 或 OUT。

停止桥接保留绑定、注册和已经完成的配对，但会结束尚在进行的配对跟踪。重新配对清理未完成时保留旧设备记录用于重试，`pairing_pending=true`，快照的 `paired_device=null`，重启也不会显示为当前设备。

发码后在有效期内跟踪，单设备保存后仍继续观察至到期；发现多个设备则全部撤销并报告冲突。停止、删除和再次配对均取消并等待旧跟踪结束。接口和异步失败字段见第 8 节“控制端只配对一台设备”。

### 删除的范围

删除一个端点采用明确的“停止使用 → 撤销远端权限 → 清理本地记录”流程。硬切换/解绑只结束链路，不调用此流程；删除 IN 不连带撤销 OUT，删除 OUT 不关闭实际 B 的远控能力。

1. 持久记录端点正在删除，禁止重新启用/同名重建；停止相关链路、续期、登录及配对任务，完成关闭后解除绑定。另一端点保留身份和授权，之后可以重新绑定。
2. IN 列出其 `environment_id` 下的配对控制端，按该 environment 与对应 client 撤销配对权限。停止签发配对码。OUT 使用已验证的接口撤销该 OUT 自己的远控 client 注册。
3. 远端撤销失败或结果不确定时，保留“本地已停用、撤销待完成”状态和完成清理所需的最少加密凭据/标识，支持重试或修复账号授权。该状态跨重启保留，不报告删除完成，不允许同名重新授权；不把旧撤销任务留到新设备授权之后执行。
4. 确认远端清理完成且旧任务全部结束后，再移除本地授权引用、注册/配对记录和清理任务，允许同名恢复。删除完成不遗留自动重试任务。

普通登录如果被其他端点共用，删除某个端点只移除其引用，不让其他端点退出登录；删除整个账号授权是另一个明确动作。租户秘密种子保留，同名恢复仍得到相同的设备 ID/签名密钥。

缺失 OUT 注册记录可按原 client ID 发起挑战核验，只有账号与原公钥一致才补回加密检查点；原编号可由管理员从备份副本离线读取。补回操作不激活端点，draft 继续显式恢复，deleting 只继续原撤权；不覆盖已有记录或解除独占。IN 注册中断时沿用原 installation ID 恢复，连接运行中自动退避重试，未完成首次注册的入口可显式重试。加密注册记录缺失但环境映射仍在时，删除和重新注册先按该环境完成撤权；撤权失败保留映射供重试。active IN 的注册记录和环境映射都缺失时报告本地记录错误，保留原对象，不当作从未配对的 draft 删除或重新注册。入口与限制见 [异常记录修复](AUTHORIZATION.md#缺失-out-注册记录的修复)。

IN 删除只撤销控制端对该虚拟环境的配对权限。迁移时验证同一控制端对其他 IN 的权限不受影响；不能把本地停止、退出登录或清除记录当成远端撤权完成。接口依据与核对范围见 [Desktop 按环境撤权](REFERENCE.md#desktop-按环境撤权)。

## 5. 租户与秘密存储

部署管理员是可信方。服务器需要无人值守签名、续期和转发，因此不承诺对主机管理员隐藏控制能力。保证普通租户之间的隔离，并降低数据库/备份单独泄漏的影响。

- 管理网页登录身份和 ChatGPT 账号授权分开；租户来自已认证管理会话，不相信请求自行指定的 tenant ID。
- IN、OUT、授权、秘密、绑定、后台任务、日志和状态订阅均限定所属租户；知道其他对象 ID 不能获得访问权。
- 数据访问限定已认证租户，使用包含租户标识的复合外键、唯一约束及事务防止跨租户关联和重复占用；对象级鉴权与隔离回归同时覆盖 API、后台任务和消息路由。
- 同账号或同名对象也不跨租户合并凭据和状态。
- 租户秘密种子及 OAuth 凭据加密保存；服务器加密主密钥通过独立 secret 文件或密钥管理服务提供，与数据库备份分开保管。
- 桌面使用受保护的本地秘密存储/系统凭据存储；不沿用把私钥与可直接解密它的口令一起备份即全部暴露的默认布局。
- 设备私钥仅在核心需要时派生/使用，前端不接收秘密种子、长期令牌或私钥。
- 日志不记录回调、令牌、配对码、私钥或聊天载荷；不同用户的活动订阅分别鉴权。

### 存储选择与边界

桌面版与自托管服务器版长期默认使用 SQLite。PostgreSQL 是条件性扩展，不列为必做阶段或交付前提。多租户、多 IN/OUT 和容器部署本身不构成更换数据库的理由。

数据库保存身份、加密凭据、授权事务、绑定、操作状态和防重放的源流记录；消息、分片、ACK、连接内 cursor 和重放队列主要由内存中的链路处理。当前新流首次进入时先持久登记，再允许转发，已有活动流不逐条写入聊天载荷。存储负载应按配置变更、续期、新流登记与管理查询评估；已有 macOS 与 OrbStack Linux 持久卷合成负载基线，方法和限制见 [SQLite 测量与恢复](STORAGE.md)。不以消息量或用户数量推定数据库瓶颈，也不把有限样本当作服务器容量上限。

默认部署由一个桥接进程拥有状态库，支持多租户和多条并发链路；SQLite 数据文件放在同机可靠持久卷。保留清晰的存储模块边界，当前按 SQLite 实际事务语义实现和验证，不预先维护第二套后端或通用数据库框架。

服务器与管理命令按数据库真实路径共享独占锁，符号链接别名使用同一锁；硬链接及目标不存在的符号链接不作为数据库入口。新租户记录与身份种子在同一事务中提交。

出现明确需求时重新评估 PostgreSQL：

- 测量表明写入争用或提交延迟已影响链路，并且合理的查询、事务及读写安排优化仍不能满足要求。
- 多台桥接主机需要共享状态，或部署方明确需要托管数据库、数据库主备及时间点恢复能力。
- 明确要求数据库级行级安全作为租户隔离的额外防线。采用时需正确设置运行角色和租户上下文；它不替代应用鉴权、内存与消息隔离，也不改变部署管理员的信任边界。

更换数据库不会自动实现多实例运行或消除远端操作结果不确定性。多机扩展还需设计链路归属、账号续期协调、故障接管及阻止旧工作进程继续操作的机制；保持现有设备身份规则，不为端点增加运行实例 ID。若增加后端，分别验证迁移、独占约束、事务与故障恢复。

当前单连接采用 `journal_mode=DELETE`、`synchronous=EXTRA`、`foreign_keys=ON`，并请求 `fullfsync=ON`（macOS 的强刷盘方式，其他平台无额外效果）。已验证连接重建保持配置、进程强杀回滚未提交事务、合成数据库离线恢复，以及数据库与独立原密钥文件恢复到新目录后启动原生服务器。已提供新流登记、凭据读写及独立连接等待/提交探针的本机负载基线；OrbStack Linux 的原生测试与卷归档恢复也已通过；正式部署的磁盘、持续负载和异机灾备仍需验证。进程强杀测试不代表断电或存储设备故障验收。评估 WAL、同步级别和读写连接安排时，以关键提交的恢复语义为约束，不以降低落盘保证换取表面性能。源流防重放记录持续增长，其保留或清理规则必须有协议依据。选型参考见 [存储依据](REFERENCE.md#存储依据)。

## 6. 协议核心

复用早期原型已验证的协议行为和回归样例，以 Desktop 的实际行为和 openai/codex 开源实现为协议对照；按新模块边界实现 Rust 核心。

- 只处理外层信封，业务 message 和分片载荷原文转发，不识别 RPC 方法、不改内部请求 ID。
- 精确处理 64 位序号，保留载荷文本、数字拼写和未来字段；用原文类型/切片避免重写内部 JSON。
- 两侧 ACK 本地消费；分别管理 cursor、发送队列、序号、重放、分片窗口及流映射。
- 普通网络重连保留原链路状态；冷启动、不可恢复缺口或流结束使用已验证的关闭/重建机制，避免旧命令重复提交。
- IN 首次出现即有不可恢复分片缺口时，先持久登记该源流的废弃决定，再发送关闭通知；同一源流后续到达或进程重启后均不能重新建立映射。登记失败时停止本次处理。
- 主动硬切换与同目标重连使用不同操作语义：硬切换关闭旧流、拒绝旧历史进入新目标，并要求新连接初始化。
- B 的真实可用性决定对应 IN 是否上线；仅 OUT socket 存在不代表 B 在线。初始在线确认、明确离线和活动证据沿用已验证边界。
- OAuth/会话续期不主动拆掉健康连接；并发续期合并完整操作，异常恢复与持续拒绝的处理明确。
- 外层格式损坏按既有政策隔离，身份错误拒绝，未知控制语义明确报告；队列有界，故障不拖垮无关链路。
- 每条链的诊断、停止和清理独立；共享账号续期在账号授权层协调。
- HTTP、WebSocket、授权回调分别使用正确网络策略；上游代理由部署统一配置，通过明确的客户端配置传递，不通过修改进程通用代理环境变量切换。
- 防止将本部署可识别的虚拟 IN 互相连接成回环。

### 部署级网络设置

2026-11-08 用户确认：代理作用于整个部署，只允许部署管理员设置，不提供租户独立覆盖。首次 setup 在上游登录前提供直连/HTTP 代理配置，管理网页提供后续修改入口；设置持久保存，重启无需重复传环境变量。部署管理员权限须与普通租户登录明确区分，不能只隐藏前端入口；代理认证信息加密保存，普通租户不能读取，管理接口也不回显密码。

设置页须区分已保存配置与实际生效配置，并说明应用变更对所有链路的重连影响。明确已有 `BRIDGE_UPSTREAM_PROXY` 的兼容及优先级，不能保存成功后仍被环境变量静默覆盖。覆盖 OAuth、控制 API 和两侧 WebSocket；网页本身及 localhost 授权回调不走上游代理。不把 ProxyBridge/TUN 等外部透明转发误报为应用内已配置代理。已实现网页“设置 → 上游代理”、setup 的网络配置和后端部署管理员鉴权。schema 7 为代理设置提供独立加密记录；首次管理用户为部署管理员，升级时仅自动识别单用户实例，多用户实例通过本机 grant-admin 明确授权。保存并应用由部署级串行操作等待各租户旧工作结束、保留启停和绑定、保存配置、替换共享 HTTP/WebSocket 网络配置，再恢复原先启用的链路；客户端断开不会取消已接受的应用操作。页面显示实际生效配置及恢复失败，密码不回显。BRIDGE_UPSTREAM_PROXY 仅在尚无保存配置时导入一次，之后以数据库为准，Bun 与独立 Rust 程序使用相同配置。

## 8. 实施顺序与完成标准

验收按功能与部署分开：同一套核心代码的真实账号功能验收可在现有本地环境完成，不因容器部署而重复授权、配对和整套远控流程。容器验证构建、启动、同源访问、持久化、权限和启停；实际服务器再检查域名、HTTPS、上游网络与代理。只有出现环境差异或新增功能时，才补相应的针对性验证。iPad/iOS 基本硬切换已按用户确认通过；审批边界、撤权等剩余功能验收独立于部署形态。

- 多 IN/OUT 独立运行、配置独占约束、共享账号续期协调。
- 实现 IN 改绑 OUT 的硬切换，关闭旧流、拒绝旧消息、提交新绑定并重新初始化。

### 2026-11-10 问题定位到具体一端：账号登录状态与链路故障归属

目标：远程控制页能直接指出哪一端、因为什么需要处理，并给出一步可完成的修复；账号页能直接看出哪个账号需要重新登录，不需要逐个“检查登录”。修复成功后，因这个原因停下的连接自动恢复。

尚未发版，本节按当前界面和流程设计，不保留旧状态名、旧字段或升级迁移。数据库直接改为当前所需结构，已有开发库手动处理。

| 用途 | 接口 | 约定 |
| ---- | ---- | ---- |
| 账号登录状态 | `GET /api/state` 的 `AccountInfo` | 新增 `sign_in_required: bool`，持久保存。存量凭据缺少 refresh token、身份与账号不符，或上游 OAuth 明确返回 `invalid_grant`、`refresh_token_expired`、`refresh_token_reused` 或 `refresh_token_invalidated` 时置为 true；普通登录成功或验证当前凭据的检查通过时清除，旧检查不得覆盖新失败 |
| 检查登录 | `POST /api/accounts/check` | 已标记时强制验证续期能力；检查结果按持久失败修订号条件清除标记，期间出现新失败则保留标记并返回 `account_sign_in_required`；明确的凭据拒绝设置标记，其他失败保持原值 |
| 重新登录 | `POST /api/accounts/login`，请求 `{expected}` | 不变。登录完成后，重启所有已启用、且因该账号登录失效而停下的连接 |
| 链路故障归属 | `GET /api/state` 的 `Chain` | 新增 `side: "controller" \| "device" \| null`，表示需要处理的一端；无法归属时为 null |
| 链路状态 | `Chain.connection` | 运行状态不变：`checking_target`、`target_offline`、`connecting`、`connected`、`reconnecting`、`stopped`。故障状态改为：`sign_in_required`（`side` 那一端的存量凭据不可用或被上游明确拒绝刷新）、`device_authorization_required`（被控端的远控授权失效，含二次授权过期、OUT 注册被拒或不存在，`side` 为 device）、`controller_registration_required`（控制端注册无法恢复，`side` 为 controller）、`access_denied`（其他 401/403，`side` 为发生的一端）、`invalid_state`（本地配置不完整，例如重新配对未完成）、`protocol_error`、`failed`。删除 `authorization_required`、`registration_required`、`input_registration_required` |

| 通用错误码 | 各操作的 HTTP 409 `error` / 桌面错误 `code` | 账号续期被拒统一为 `account_sign_in_required`；被控端授权失效统一为 `device_authorization_required` |

界面：连线只表示连接状态；故障时 `side` 那一端的卡片标为需要处理，卡片上写明原因并给出唯一操作（重新登录该账号、重新授权被控端、重试控制端注册）。账号页把 `sign_in_required` 的账号排在最前，标明受影响的控制端和被控端，并提供“重新登录”；“检查登录”保留为手动检查。

后端实现（2026-11-10）：存量凭据缺失、缺少 refresh token、所属身份不匹配或刷新返回身份不符，以及 OAuth 明确返回 `invalid_grant`、`refresh_token_expired`、`refresh_token_reused` 或 `refresh_token_invalidated` 时，持久设置 `accounts.sign_in_required` 并递增 `sign_in_revision`；当次登录回调中的身份校验仍只拒绝该次登录。快照不读取身份不匹配凭据的显示名称，保留账号及登录标记供界面修复。无 OAuth 错误体的 4xx（含网关 403/404）、408、429、5xx 和网络失败继续退避重试，不设置标记。其他明确的 OAuth 错误（如 invalid_client、unauthorized_client、invalid_request、unsupported_grant_type）在实际来源一端报告 `failed`，停止自动重试且不设置登录标记，允许手动重试；操作错误沿用 `upstream_auth_rejected`，不新增公开状态或错误码。已标记账号的登录检查实际执行续期，`accounts.sign_in_revision` 在每次凭据拒绝时递增，检查仅能按开始时修订号清除标记，过时结果返回 `account_sign_in_required`。两侧凭据、目标探测、注册和握手错误保留实际来源，OUT 注册或二次授权失败使用 `device_authorization_required`，仅控制端注册确实缺失或明确失效时使用 `controller_registration_required`；重新注册遇到普通 401/403 保留为 controller 侧 `access_denied`，不自动恢复。注册读取、解析或解密失败报告带侧别的本地 `invalid_state`。active 且有可恢复检查点的 OUT 继续通过 `/outputs/{id}/recover` 恢复，并重启匹配的已启用故障连接。协调器在账号登录、被控端授权和控制端重新注册成功后，只重启与修复原因及账号/端点匹配的已启用连接；手动停止和其他连接保持原状。网页与桌面继续共用快照、操作和错误码，路径不变。数据库当前版本为 14，与历史版本 1–13 区分；只初始化空库、接受当前版本，其他版本及非空无版本库在打开时明确报告结构不受支持、需要手工处理，不提供迁移。合成回归覆盖两侧续期拒绝、身份变化、二次授权与注册失败、持久标记重开数据库、修复后的隔离恢复及两种传输的回复；本轮未连接真实上游。

补充（2026-11-12）：字符串 `error` 继续按 OAuth 错误处理；嵌套 `error.code` 和顶层 `code` 只识别 invalid_grant、refresh_token_expired、refresh_token_reused、refresh_token_invalidated 四个明确凭据失效码，其他 code 保持临时失败，避免把网关响应误当成 OAuth 拒绝。刷新凭据失效统一进入既有的持久登录标记、修订号及 `account_sign_in_required` 路径；检查登录和两侧运行中的续期共用此分类。仍先按 HTTP 状态区分，408、429、5xx 即使携带这些错误码也保持临时失败。其他明确 OAuth 错误仍停止自动重试，普通网关错误仍重试，网页和桌面的公开接口不变。新增本地 HTTP 回归覆盖三种失效码的响应格式、检查登录、修订号、错误码及故障侧别。

界面：概览和控制端页面显示时，对每个已注册、未在删除的控制端调用一次核对，“刷新状态”也会调用；后端负责 30 秒节流，前端不做计时。卡片只显示设备名称；控制端页面的设备区按 Desktop 显示名称、平台，以及“上次连接 {时间}”或“已授权设备”。服务端有多台设备时，卡片标为“多台设备”，操作为“重新配对设备”。

后端实现（2026-11-11）：网页 `/api/inputs/{id}/device/sync` 与桌面 `/inputs/{id}/device/sync` 共用租户协调器操作，网页返回 204，桌面返回空值。同步不启动或停止链路，也不发起注册；只使用当前租户该 IN 的已保存环境。协调器跳过仍在运行的配对跟踪，`endpoints.device_checked_at` 持久保存最近一次同步尝试的开始时间，30 秒内重复请求（含上次读取失败）直接返回。有效列表的单设备更新、零设备清除都只写本地记录；多设备保留记录和配对状态，仅设置 `in_multiple_devices`，不撤权。该提示在下次配对开始时清除。读取或时间字段解析失败保留设备及错误；账号凭据被明确拒绝时仍持久标记并通知界面。仅设备、错误或账号登录标记有变化时发出通知，节流和未变化的列表不触发刷新循环。配对与同步共用元数据转换：名称跳过空白，依次取 display_name、device_model、platform；上游 RFC3339 的 last_seen_at 转成 Unix 秒，缺少字段时为 null。快照仍只读本地，配对中断的 pending 不由同步操作解除。当前 schema 为 14，开发库手工处理，无迁移。合成回归覆盖节流与重开数据库、配对跟踪跳过、名称/身份及展示字段更新、无设备、多设备不撤权与重新配对清除提示、读取失败与账号标记，以及网页/桌面的空回复和错误一致；未连接真实账号或上游。

### 2026-11-11 被控端电脑记录与服务端同步

问题：电脑名称只在配对时写一次，之后只有运行中的连接在探测在线状态时顺带更新。未绑定或已停止的被控端永远不会刷新，旧数据会一直显示“未命名电脑”，也看不到电脑是否在线。Desktop 不依赖连接，单独刷新整份电脑列表（`refreshRemoteControlConnections` 读取 `/clients/{client_id}/environments`，名称依次取 display_name、name、host_name，同时带 online 与 last_seen_at）。做法与控制端设备同步对称。

| 用途 | 接口 | 约定 |
| ---- | ---- | ---- |
| 电脑状态 | OUT 的 `EndpointInfo` | 新增 `target_online: bool \| null` 与 `target_last_seen_at: number \| null`（Unix 秒），持久保存，读取快照不访问上游；`target_name` 含义不变 |
| 核对电脑 | `POST /api/outputs/{id}/device/sync`，桌面同名命令 | 返回 204。距上次核对不足 30 秒、正在重新配对或未授权时直接返回、不访问上游。否则读取该 OUT 可访问的电脑列表：包含当前目标时更新名称、在线和最近在线；不包含当前目标时保留目标，`pairing_error` 设为 `out_target_missing`（电脑不再授权给这个被控端）；另有其他电脑时保留目标，`pairing_error` 设为 `out_multiple_environments`。两种提示都不自动撤权，重新配对后清除。读取失败保持原值，账号登录失效照常设置账号标记。有变化时发出状态更新 |
| 运行中的连接 | 探测 | 继续按现有方式更新名称与在线证据，同时写入上述字段，两条路径写同一份记录 |

界面：概览和被控端页面显示时、以及“刷新状态”时，对每个已授权、已有电脑、未在删除的被控端调用一次核对，节流由后端负责。未连接的被控端卡片显示“在线 / 离线”；电脑区显示名称、在线状态和“上次在线 {时间}”。`out_target_missing` 与 `out_multiple_environments` 标为需要处理，操作为“重新配对电脑”。

后端实现（2026-11-11）：网页 `/api/outputs/{id}/device/sync` 与桌面 `/outputs/{id}/device/sync` 共用租户协调器，分别返回 204 与空值。显式核对不依赖绑定或链路启停，不启动连接、不注册或撤权；未授权、没有目标或存在未完成重新配对记录时跳过。与 IN 共用 `endpoints.device_checked_at` 的持久 30 秒节流，读取失败也计入本次尝试。配对、显式核对和运行中探测统一写 `target_records`：名称依次取非空白 display_name、name、host_name，online 可空，RFC3339 last_seen_at 转 Unix 秒。记录仅在仍属于当前目标且未重新配对时更新。目标缺失优先于额外电脑提示，保留目标和上次已知元数据；失去访问权限不等于电脑离线，运行中连接仍按既有规则断开。额外电脑只记录提示；两种提示都保留至重新配对成功，并在保存新目标的同一事务内清除、重置同步节流。读取或字段解析失败保留记录，账号凭据明确失效仍设置登录标记。只有记录、提示或账号标记变化才通知，快照始终只读本地。当前 schema 为 14，开发库手工处理，无迁移。合成测试覆盖未绑定刷新、节流和重开数据库、重新配对与未授权跳过、目标缺失及多电脑不撤权、重新配对清除、读取失败与账号标记、运行探测与核对共用记录，以及网页/桌面空回复与错误一致；未连接真实账号或上游。

### 界面、导航与语言约定

- 界面角色只有控制端和被控端（定义见第 2 节）。用户文案不要求先理解 IN/OUT；需要指明内部对象时写“入口 IN”“出口 OUT”。
- 网页页面进入 URL，刷新、前进和后退保留页面；App 品牌标识不触发跳转，重新显示窗口保留当前页面。
- 英文为项目基础语言，中文翻译单独维护；README.md 为英文，README_zh.md 为中文。界面默认跟随客户端系统语言，不支持的语言回退英文。
- App 语言位于设置的通用区域；网页语言位于右上角，属于个人显示偏好，不受部署管理员权限限制。
- App 原生主菜单与托盘同步语言；切换语言时清除上一语言的临时操作提示。
- 新建端点按稳定账号身份保存选择，实时更新不改变所选账号。绑定与切换按设备 ID 保存出口选择；所选出口不可用后清空选择并要求重新选择。状态读取失效时，页面和已打开弹窗均暂停变更；旧会话的迟到响应不改变新会话导航。初始会话查询完成后才展示登录或管理页面。
- 网页状态快照携带本次请求对应的管理会话身份与 CSRF；发现共享 Cookie 已切换会话时，清空旧数据、弹窗和操作状态，再订阅新会话并重新读取快照。同一用户重新登录也按新会话处理。
- 网页、App 与单步 CLI 的检查登录均通过同一上游只读请求验证授权，按现有规则处理令牌续期；被控端在线状态由连接观测单独呈现。
- 导航为“远程控制 / 账号 / 设置”。远程控制页是一块配线板：左列控制端，右列被控端；已连接的一对占一行，中间的连线表达状态（实线已连接、虚线连接中、点线电脑离线、断线故障、细线已停止），状态同时用文字写出，仅已连接线路有一处流动效果并遵守减少动态效果设置。连接因某一端的问题停下时，原因和修复写在那一端的卡片上并标为红色，连线旁只保留停止；没有归属的故障在连线旁给出重试。未连接的控制端和被控端列在下方，各自提供“连接”。没有任何端点时显示两个添加入口。
- 卡片标题是用户起的固定名称；控制端卡片显示它唯一的设备名称（手机、平板或桌面端），被控端卡片显示电脑名称（Desktop 顺序 display_name、name、host_name 的缓存）和在线状态，账号作为小字标注。注册未完成、待授权、未配对电脑、待清理、记录缺失、账号登录失效、被控端授权失效和控制端注册失效等情况直接写在卡片上（尚待完成的设置标为琥珀色），并给出唯一的下一步操作。账号页把需要重新登录的账号排在最前，列出使用它的控制端和被控端，提供“重新登录”和“检查全部登录”。
- 控制端页面（`#/controllers/<IN ID>`）：连接面板（状态、启停、切换被控端、断开）、设备（名称、平台、重新配对）、详细信息（账号、固定名称、IN ID、删除）。被控端页面（`#/devices/<OUT ID>`）：连接面板（启停、断开）、电脑（名称、ID、重新配对）、详细信息与删除。旧的 `#/connections/<IN ID>` 打开对应控制端页面，`#/in`、`#/out`、`#/endpoints` 打开远程控制页，地址栏随之改为新地址。
- 新建控制端：选择用来控制的设备上登录的账号并命名，创建后直接显示配对码。新建被控端：选择电脑上登录的账号并命名，创建后直接进入授权，授权保存后直接进入配对电脑。两个对话框都可以先添加账号，登录完成后回到原对话框。连接与切换的选择按设备 ID 保存，所选对象不可用后清空并要求重新选择。
- 操作成功提示在工作区内数秒后自动消失，失败提示保留到下一次操作；用户切换页面时清除旧提示。实时状态以页首的小状态点显示，不常驻实现细节说明。
- App 内品牌、程序图标和托盘采用一致的双向箭头图形；托盘使用单色版本，不附加 RC 缩写。

### 2026-11-09 授权与 IN 注册恢复修复

Step-up 新鲜度按 Desktop 使用秒级 iat 与毫秒级密码认证时间，只检查五分钟上限，保留身份、scope 和过期校验。桌面回调先选择 1455 / 1457 再生成授权事务；Host 与事务端口一致，端口均占用时使用手动回调。网页服务器继续由用户提交本机回调。

IN 的 server/refresh 返回 404，或 IN WebSocket 握手 404 明确表示 `Remote app server not found` 时，先结束并等待旧连接任务、废弃旧流，再用原 installation ID 重新 enroll。其他握手 404 保留注册并退避重试；IN 握手 401/403 刷新 server token，不强制刷新账号 OAuth。配对恢复使用绑定被控端的 app_server_version；未绑定时使用桥接版本。同一 IN 的恢复串行处理，晚到的旧 server 失效通知复用已保存的新注册。

IN 首次注册和重新注册共用按设备串行的恢复流程，沿用原账号、名称和 installation ID。超时、5xx、应答丢失、无效成功响应及保存失败可重试；运行中的链路按既有退避规则自动重试，停止或删除会结束重试循环并等待已发送请求完成。成功注册加密保存，与环境映射同事务提交，再重建运行任务；deleting 端点保存清理所需的注册但保持停用。首次注册未完成时可在控制端卡片或页面重试并获取配对码。IN 不再使用注册未知结果的预写屏障，当前结构仅保留 OUT 授权恢复记录。删除按当前已保存的环境撤销控制端权限后清理本地状态，不为删除发起新 enroll。加密注册缺失时使用同租户、同 IN 的独立环境映射；重新注册也先清理该环境的控制端权限，清理完成后才允许覆盖映射，部分撤权或新注册失败保留原映射。active IN 两份标识都缺失时拒绝删除及重新注册并保留对象。向导、bridge-admin 创建/配对入口与管理端共用按设备串行的恢复流程，已有注册先 refresh，404 后沿用原身份 enroll；配对使用绑定被控端版本，未绑定使用桥接版本。

被控端元数据缺少 online 时视为没有新的在线证据，继续探测并沿用已有证据的到期规则。OUT 注册和续期接口的 401 先尝试账号续期；账号续期被拒报告账号需要登录，账号有效而注册接口仍返回 401/403/404 时报告被控端需要重新授权。其他接口或握手的 401/403 保留为对应一端的访问被拒。Step-up token 必须包含当前账号的成员身份，保留旧字段 account_user_id 的兼容读取。

### 2026-11-12 网页用户管理

目标：服务器部署的日常用户管理不再需要停服务、进命令行。部署管理员在网页上添加、删除用户并重置他人密码，每个用户可以自己修改密码；命令行保留作恢复入口，用于首次初始化、所有管理员都无法登录，以及授予管理员。一次完成，不分期。

对象：一个管理用户对应一个空间（租户）。`management_users.tenant_id` 唯一，保证每个空间最多一个管理账号；网页添加用户在同一事务里建齐租户、租户种子和管理账号，不产生没有账号的空间。命令行单独 `new-tenant` 后暂时没有账号的空间不出现在用户列表里，仍由命令行处理。数据库结构不变，版本保持 14。

权限：用户管理接口只对部署管理员开放，后端鉴权，不能只隐藏入口。网页只能操作非管理员用户：不能重置或删除任何部署管理员，自己也包括在内；授予和取消管理员只能用命令行 `grant-admin`。因此网页不可能删掉最后一个管理员。管理员看到的只有用户名和账号状态，看不到其他空间的 ChatGPT 账号、设备和连接。

接口：所有写操作沿用现有的 CSRF 和会话检查；`id` 是 `management_users.id`。

| 用途 | 接口 | 成功 | 约定 |
| ---- | ---- | ---- | ---- |
| 用户列表 | `GET /api/users` | 200 `{users:[{id, username, deployment_admin, locked, current}]}` | 按用户名排序；`locked` 表示当前处于登录锁定期；`current` 标记调用者自己 |
| 添加用户 | `POST /api/users`，`{username, password}` | 201，返回该用户的列表项 | 新空间的协调器、事件流限额立即生效，不重启服务器 |
| 重置他人密码 | `POST /api/users/{id}/password`，`{password}` | 204 | 同时清零失败次数、解除锁定，删除对方全部管理会话 |
| 删除用户 | `DELETE /api/users/{id}` | 204 | 删除整个空间，不撤销上游注册，见下文 |
| 修改自己的密码 | `POST /api/session/password`，`{current, password}` | 204 | 保留当前会话，删除自己的其他会话 |

错误码：非管理员 403 `deployment_admin_required`；用户名不合法 400 `invalid_username`；密码不合法 400 `invalid_password`；用户名已存在 409 `username_exists`；用户不存在 404 `user_not_found`；目标是部署管理员（含自己）409 `target_is_admin`；当前密码错误 400 `current_password_incorrect`；处于锁定期 429 `login_rate_limited`。当前密码错误不能返回 401：前端收到 401 会退出管理登录。用户名和密码规则沿用 `management.rs` 的 `validate`（用户名为小写字母、数字和 `_.-`，最长 64；密码至少 12 个字符、最多 1024 字节），只是拆成两个错误码。

并发：本人改密码的写入沿用登录的做法，在写事务里用 `WHERE password_hash=?` 确认验证时读到的哈希仍未变化，不新增版本列。修改自己密码时，同一事务还要确认当前会话仍然存在；任一条件不满足就按当前密码错误或会话失效处理，不能覆盖管理员刚设置的密码，也不能保留已被撤销的会话。当前密码输错计入与登录相同的失败次数和锁定。网页上所有密码验证和哈希计算都经过 `ManagementAuth` 现有的哈希并发限制，命令行专用的函数不直接暴露给网页。

运行中的空间注册表：协调器、按空间的事件流限额和退出时需要等待的任务由同一个注册表管理，支持运行中加入和移除。加入、移除和上游代理切换互斥（沿用 `network_gate`），代理切换只遍历当时注册的空间。添加和删除一旦被接受就交给后台任务完成，浏览器断开不会留下半完成的状态；请求本身等待任务结束再回复。服务器正常退出时等待动态加入的协调器。

删除：管理员删除是强制手段，不向上游撤销控制端或被控端注册。整个空间连同种子、加密凭据和设备密钥一起删除后，这些注册再也无法使用，不构成安全风险；而要求撤销成功会让最需要清理的、登录早已过期的空间删不掉。代价是该用户的 ChatGPT 里可能留下失效的设备或配对记录，由界面在确认时说明。顺序：先从注册表移除，使该空间的新请求失败；再停止它的协调器并等待进行中的操作结束；最后在一个事务里删除该空间所有带 `tenant_id` 的行、管理账号和会话。删除顺序要满足外键和 `binding_reserved_*`、`target_reserved_*` 触发器，必要时先删 `chain_switches`。事务提交前中断时什么都不删，重启后空间照常运行，可以重新删除。

失效范围：这些操作只影响管理登录，不停止用户正在运行的桥接连接（删除用户除外）。`/api/events` 已在每次发送事件和心跳前重新检查会话，失效后发出 `session_expired` 并结束，无需另做断流。

完成标准：合成数据回归覆盖以下情况并通过 cargo test 与 clippy。非管理员访问全部接口被拒绝；各错误码按上表返回。新用户不重启即可登录、读取状态、订阅事件，并参与之后的代理切换和服务器正常退出。重置后对方所有会话和事件流失效，其运行中的连接不受影响。修改自己的密码后当前会话及其事件流保留、其他会话失效。“旧密码登录与重置并发”和“本人改密码与管理员重置并发”都不会让旧密码或被撤销的会话继续有效。删除一个拥有账号、控制端、被控端、绑定、切换记录、配对和登录事务的空间后，该空间的数据全部消失，其他空间的数据、连接和事件流不受影响，删除过程中不访问上游。前端的用户页和改密码对话框另行实现。

后端实现（2026-11-12）：五个接口按上表接入；服务器以一个运行时注册表持有空间的协调器、事件流限额、独立停止令牌及任务句柄，启动时和运行中新建的空间使用同一路径。添加、删除与代理切换通过 `network_gate` 写锁串行，其他受保护请求持读锁；三种部署操作共用后台任务跟踪，正常退出先等待已接受操作，再停止并等待注册表内全部协调器。删除先移除空间并等待当前操作及链路结束，随后原子清理本地全部空间数据，不调用上游撤权。若本地删除事务失败，数据回滚，在持有 `network_gate` 写锁期间将原空间重新加入注册表，恢复状态读取、事件订阅及已启用连接，再返回原来的错误，管理员可以再次删除。

网页密码计算使用现有 `workers`，管理员添加用户和重置密码等待可用额度，本人改密的验证及哈希计算在额度不足时仍立即返回 429。阻塞计算即使调用者断开也持有并发额度直到结束。本人改密在事务内同时核验会话、原密码哈希和锁定时间，管理员重置直接覆盖非管理员用户的密码，清零失败次数和锁定并删除其全部会话，不核验原哈希；本人改密因并发写入使原哈希失效时返回 400 `current_password_incorrect`，会话已撤销时返回 401 `login_required`。当前密码错误累计登录失败次数，进入锁定期后的请求返回 429 `login_rate_limited`。数据库结构和版本 14 保持不变，命令行命令行为保留。

新增合成测试覆盖密码验证与管理员重置的受控交错、当前会话保留和其他事件流失效、失败次数与锁定、创建失败事务回滚、网页权限及错误码、动态空间事件订阅和代理切换、HTTP 取消后添加及删除仍完成、退出等待动态任务，以及带切换保留记录等全部空间表数据的删除。运行中的合成链路验证重置密码不中断连接、删除等待链路结束且其他空间继续运行。前端另行实现，本轮不连接真实账号或上游。
